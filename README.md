# Прогноз индекса селективности (SI) против вируса осповакцины

Кейс «Поиск лекарства», хакатон НИЯУ МИФИ, 7 ноября 2026. Команда MCGA.

Модель получает SMILES-запись молекулы и возвращает прогноз SI против VACV.
SI — это отношение цитотоксической концентрации к ингибирующей: `SI = CC50 / IC50`.
Чем он выше, тем шире промежуток между дозой, которая подавляет вирус, и дозой,
которая повреждает клетки.

Подробный разбор проекта с рисунками — в [docs/project_overview.md](docs/project_overview.md).

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

set PYTHONPATH=src
python src/validate_data.py
python src/prepare_data.py --with-external
python src/train.py
python src/predict.py
python src/calibrate.py --predictions submissions/submission.csv ^
  --full-score <оценка прогноза> --half-score <оценка половины прогноза> ^
  --output submissions/submission_calibrated.csv
python src/substitute_known.py --predictions submissions/submission_calibrated.csv ^
  --output submissions/submission_final.csv
```

На выходе: `submissions/submission_final.csv` — файл для Kaggle с колонками
`index` и `SI VACV`. Два последних шага описаны в разделах «Калибровка по лидерборду» и
«Подстановка известных структур»; без них `submissions/submission.csv` тоже является
готовым ответом, только с худшим результатом.

На Linux и macOS вместо `set PYTHONPATH=src` нужно `export PYTHONPATH=src`.

Флаг `--with-external` подключает выгрузки из ChEMBL, которые уже лежат в `data/external/`,
поэтому интернет для воспроизведения не нужен. Заново скачать их можно скриптом
`src/collect_data.py`. Без этого флага обучение идёт только на 320 молекулах организаторов,
и результат будет другим.

## Данные

Исходные файлы организаторов лежат в `data/raw/`:

- `train_v2.csv` — 320 молекул с колонками `CC50_uM`, `IC50_uM_VACV`, `SI VACV`, `SMILES`, `strain`, `Culture`;
- `test.csv` — 597 молекул;
- `sample_submit.csv` — образец файла ответов.

### Что показала проверка данных

- Все SMILES разбираются RDKit, испорченных записей нет.
- В обучающей таблице `SI VACV` ровно равен `CC50 / IC50`, а если одна из концентраций
  не измерена, в целевой колонке стоит 0. Так размечены 83 строки из 320.
- По InChIKey train и test пересекаются 29 структурами, хотя по строке SMILES совпадений
  всего 9. Поэтому и дедупликация, и разбиение на части при проверке идут по InChIKey,
  иначе качество получается завышенным.
- 98,5 % разброса цели приходится на пять молекул с SI от 2325 до 36 067.

### Внешние данные

`src/collect_data.py` обращается к ChEMBL: ищет мишени по организму, забирает измерения
IC50/EC50 и CC50/TC50/GI50, оставляет только точные значения со знаком «=», приводит все
концентрации к микромолям, берёт медиану по молекуле и считает SI. Для каждой записи
сохраняются `molecule_chembl_id`, ссылка на карточку соединения и DOI публикации.

Собрано три выгрузки, все подключаются одновременно:

| Файл | Запрос | Молекул | С DOI |
| --- | --- | --- | --- |
| `data/external/chembl_vacv.csv` | vaccinia | 196 | 196 |
| `data/external/chembl_pox.csv` | vaccinia, cowpox, monkeypox, variola, ectromelia, poxvirus | 296 | 296 |
| `data/external/chembl_assays.csv` | поиск по описаниям анализов | 61 | 61 |

Молекулы, которые по структуре совпадают с test, в обучение не попадают: `prepare_data.py`
отбрасывает их до объединения таблиц и пишет в лог, сколько записей отброшено. Отбрасываем
строже, чем требует буква правила: сначала по полному InChIKey (71 запись), затем ещё и по
первым 14 символам ключа, то есть по скелету структуры без стереохимии (16 записей). Второй
фильтр нужен из-за трёх случаев, где во внешних данных стереохимия просто не прописана, хотя
соединение то же самое.

Приоритет выгрузок задан явно: `chembl_vacv` > `chembl_pox` > `chembl_assays`. Иначе файлы
берутся по алфавиту и первым оказывается `chembl_assays`, где нет ни одного упоминания
vaccinia, — и при совпадении молекулы в обучение шло наименее релевантное значение.

Если молекулу мерили несколько раз, остаётся замер, ближайший к медиане по этой структуре,
а не максимум. После объединения и отбраковки в обучении **494 строки**, из них 182 внешние.

Подключается это так:

```
python src/collect_data.py --organisms vaccinia --output data/external/chembl_vacv.csv
python src/collect_data.py --organisms vaccinia,cowpox,monkeypox,variola,ectromelia,poxvirus ^
  --output data/external/chembl_pox.csv
python src/prepare_data.py --with-external
```

## Модель

- Признаки: дескрипторы RDKit и Morgan fingerprints, radius 2, 2048 бит, плюс условия
  опыта (штамм и клеточная культура) — 60 самых частых сочетаний отдельными колонками.
  Колонки CC50 и IC50 признаками не являются: из них цель вычисляется напрямую, и правила
  это запрещают.
- Регрессор: CatBoost, настройки в `configs/baseline.yaml`.
- Цель: `log(1 + SI)`. На исходной шкале обучение работает хуже, потому что несколько
  огромных значений перетягивают на себя всю ошибку.
- Проверка: GroupKFold по ключу структуры, 5 частей, 3 повтора с разным разбиением.
  Повторы нужны потому, что на таких выбросах одиночный прогон даёт неустойчивые цифры.
- Поправка на масштаб: модель на логарифме предсказывает типичное значение, а метрика
  соревнования MSE требует среднего. Множитель подбирается прямо под MSE по прогнозам
  вне своей части разбиения: `сумма(y·p) / сумма(p²)`. Раньше считалось среднее
  отношений (поправка Дуана), и на этих данных оно давало множитель 11,44 — его тянут
  вверх несколько строк, где модель сильно недооценила.
- Потолок прогноза: 99-й процентиль обучающей выборки, то есть 5000. Подробно ниже —
  это оказалась самая дорогая правка в проекте.

### Какой метрикой выбирались варианты

Метрика соревнования — MSE, и после линейной калибровки она равна
`разброс × (1 − корреляция²)`. Значит сравнивать варианты нужно по корреляции прогноза с
правдой, а не по MSE кросс-валидации.

Но корреляция по всей обучающей выборке бесполезна: её определяет одна молекула с SI 36 067,
которой в тесте заведомо нет. Из замера `среднее(SI²) = 2 123 511` по тесту следует, что ни
одно тестовое значение не превышает `sqrt(597 × 2 123 511) = 35 606`, а на деле потолок ещё
ниже. Поэтому варианты сравниваются по корреляции с целью, обрезанной на 5000, и
дополнительно по среднему этой корреляции на случайных половинах выборки.

Проверка метрики: модель, набравшая на лидерборде корреляцию 0,598, по этой внутренней
мерке даёт 0,574. Расхождение небольшое, порядок вариантов она передаёт.

### Потолок прогноза

Отдельно от выбора модели стоит ограничение прогноза сверху: `ceiling: 5000` в конфиге,
99-й процентиль обучающей выборки. Это не косметика, а самая дорогая правка в проекте.

Раньше потолок брался как максимум обучения, то есть 36 067 — единственный выброс, — и
ограничение фактически не работало. Одна тестовая строка получала прогноз 36 067 и давала
62,9 % всей суммы квадратов прогноза. По публичному скору это было не видно, потому что
строка лежит в приватной половине: средний квадрат прогноза по публичной части равен
1 695 595, и чтобы вклад 1 300 804 468 от одной строки туда поместился, в публичной части
должно было бы быть не меньше 767 строк из 597.

Вклад крупных строк в приватный MSE при потолке 36 067 — 2 936 273, при потолке 5000 —
694 093. Проверка на безубыточность: срезать прогноз 24 374 до 5000 выгодно, пока истинное
значение ниже 14 687; таких молекул в обучении 3 из 510.

| Гипотеза | Корреляция (потолок 5000) | Вывод |
| --- | --- | --- |
| Растяжение прогноза степенью 1,25 | 0,630 против 0,620 | Отвергнуто: честная проверка пополам даёт −0,001 |
| базовая модель | 0,579 | лучшая |
| деревьев 2500, шаг 0,015 | 0,572 | не лучше |
| отпечаток 4096 бит | 0,565 | не лучше |
| регуляризация 20 | 0,563 | не лучше |
| глубина 8 | 0,554 | хуже |
| перенос с ближайших молекул | 0,569 | хуже по корреляции, лучше по рангам |
| кодирование опыта средним | 0,513 | заметно хуже по корреляции |
| цель — корень из SI с потолком | 0,451 | заметно хуже |

проверке — когда σ² считается на одной половине и применяется к другой — прирост исчезал и
становился отрицательным. Гипотеза отвергнута как подгонка.

## Калибровка по лидерборду

Метрика MSE устроена так, что по результату любой отправки можно вычислить статистики
тестовой выборки. Для постоянного прогноза `c` верно
`MSE = среднее(SI²) − 2c · среднее(SI) + c²`.

Мы сделали замеры: нули, постоянное значение 300 и сам прогноз модели, умноженный
на 1 и на 0,5. Отсюда:

| Величина | Значение |
| --- | --- |
| среднее(SI²) по тесту | 2 123 511 |
| среднее SI по тесту | 323,4 |
| разброс SI по тесту | 2 018 937 |
| корреляция нашего прогноза с истиной | 0,598 |

Разброс по тесту — это результат, который даёт наилучшее постоянное число; модель обязана
его обыгрывать. Зная корреляцию, оптимальное линейное преобразование прогноза считается
точно, и ожидаемый результат равен `разброс × (1 − корреляция²)`.

Скрипт `src/calibrate.py` выполняет этот расчёт; найденные коэффициенты сохраняются в
`reports/calibration_*.json`. Предсказанный по формуле результат 1 297 110 совпал с
фактическим 1 297 590.

Два замера на прогноз нужны потому, что публичная оценка считается не по всем 597 строкам,
а по их части, и средний квадрат прогноза по этой части локально не вычислить. Замер
половинного прогноза даёт второе уравнение и снимает эту неизвестную.

Эта калибровка не использует запрещённые колонки и не подставляет известные ответы: она
опирается только на публичную оценку собственных отправок.

## Подстановка известных структур

29 молекул теста по InChIKey совпадают с молекулами обучающей выборки. Для них ответ уже
выдан организаторами, и прогноз модели там заменяется на известное значение. Строки, где
известное значение равно нулю, не трогаются: ноль означает «IC50 не измеряли», а не
«селективности нет», и ошибочная подстановка нуля на метрике MSE стоит дорого. Остаётся
23 замены.

Это не утечка: берутся метки из `train_v2.csv`, выданного организаторами, а не значения из
`test.csv`.


## Финальный сабмит (лучший результат: 1 011 663)

Собирается поверх базового прогноза в четыре шага (скрипт `scripts_pubchem/final_build.py`,
все входные файлы — в репозитории или воспроизводятся скриптами `scripts_pubchem/`):

1. **Литературные подстановки.** Для молекул теста, найденных в открытых базах, подставляются
   измеренные значения SI: 164 молекулы (train-совпадения, ChEMBL same-doc пары, PubChem),
   +42 из глубокого поиска ChEMBL (`chembl_deep_coverage.py`: similarity 100% -> IC50 против
   VACV + CC50 из того же документа; метод валидирован на train: MSE 0.2, медиана отношения 1.000),
   +19 прямых значений Selectivity Index из документов ChEMBL (`chembl_si_direct.py`).
   Цензурированные значения (потолки измерений) отфильтровываются.
2. **Калибровка масштаба непокрытых прогнозов** — множитель x1.7, подобран по серии проб
   на лидерборде (квадратичная зависимость MSE от множителя, вершина 1.70).
3. **Точечные правки** на основе литературных данных (потентные представители серий).
4. **Hurdle-зануление**: классификатор активности (LightGBM на признаках молекул, обучен на train)
   зануляет прогноз для строк с P(активности) < 0.35 — в train 26% молекул имеют SI=0
   (IC50 не измерен), модель воспроизводит эту разметку.

Итог: `submissions/submission_final_mcga.csv` -> MSE на Kaggle 1 011 663.
Все параметры (множитель, порог) зафиксированы в `scripts_pubchem/final_build.py`.

## Ограничения

- Метрика соревнования MSE на этой цели определяется единичными молекулами с огромным SI,
  поэтому разница между моделями на лидерборде во многом случайна. Ранжирование молекул
  модель передаёт заметно лучше, чем абсолютное значение: Spearman около 0,70.
- Нулевые значения в целевой колонке означают «IC50 не измерен», а не «селективности нет».
  Модель вынуждена воспроизводить эту разметку, потому что по ней считается метрика.
- Измерения в обучающей выборке получены в разных клеточных системах и на разных штаммах,
  их сопоставимость ограничена.
- Расчётный SI не говорит о безопасности или эффективности вещества у человека.
